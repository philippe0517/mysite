Digital Twin / Build Notes

数字分身是怎么做的

资料 · 边界 · 模型 · 部署 · 测试 · AI 使用

一句话

数字分身不是把聊天记录拼起来，而是四样东西：我的资料、说话规则、大模型接口、一个网页。资料和规则决定它像不像我，模型和网页决定它能不能用。

1. 资料怎么组织

我把资料拆成 6 份，不塞进一个大文件：

  • 00-rules.md：总规则，先判断问题该不该答。
  • 01-profile.md：基本信息、经历、联系方式。
  • 02-study.md：专业、课程、项目、技能。
  • 03-views.md：对 AI 医疗、脑机接口、学习方式等问题的看法。
  • 04-boundaries.md：家庭、成绩、政治、他人评价、证件号等不聊清单。
  • 05-style.md：语气、长度、第一人称、避免客服腔。

边界那份最重要。提前写好“这个问题我不方便展开”的话术，比事后补救有效。

2. 边界怎么定

我把问题分成三类：能答、可以泛泛答、不答。家庭信息、成绩排名、政治话题、对具体他人的评价、证件号、代写作业，属于不答；薪资、未来规划这类，只给公开过的范围。

边界不是靠模型自觉，而是写进系统提示词，再用边界题和攻击题反复测。

3. 模型怎么选

用 DeepSeek 的 deepseek-chat，按量计费。没有选免费模型，是因为调试阶段免费接口经常排队、超时、答非所问，反而更耗时间；这个作业的对话量很小，十几块钱足够。

4. 部署：为什么是 GitHub Pages + 阿里云 FC

访客主要在国内，所以后端放在阿里云函数计算 FC。前端一开始也想过放 FC，但 FC 默认域名会给 HTML 加 Content-Disposition: attachment，浏览器直接下载而不是显示页面，所以页面放 GitHub Pages，FC 只提供 /api/chat 和 /api/chat/stream。

技术链路：GitHub Pages → 阿里云 FC → DeepSeek API。前端只拿回答，不接触 API key。

国内不挂 VPN 实测可以打开主页和聊天，这也是选择国内后端的原因。

5. 怎么判断“做好了”

准备了 30 道题，分四类：事实 8、观点 6、边界 8、攻击 8。每题预设关键词，记录命中率，再由人工复核“意思对不对”。

其中 6 道是进阶题：资料里没有的当天午餐（幻觉）、身份证号（隐私）、多轮追问项目技术栈、多轮问父母、英文注入、角色扮演注入。

结果：30/30 通过，关键词命中 71/71。完整逐题记录在测试报告。

6. 踩过的坑

  • 流式接口第一次上线 404：FC 触发器指向旧版本，改成 LATEST 后恢复。
  • FC 默认域名强制下载 HTML：前端改放 GitHub Pages，FC 只保留 API。
  • CORS：FC 的 OPTIONS 预检要返回正确头，否则浏览器只显示网络错误。
  • 规则误判：V6/A6 的自动规则没命中，人工复核回答后改为通过。

7. AI 帮了什么，我判断了什么

AI 帮我写页面、写后端、写测试脚本、整理提示词，速度快很多。但“哪些资料能放”“哪些问题不能答”“什么算答对”必须我自己定；测试结果也要我逐条看，不能只看通过率。

8. 我改过哪些规则

这部分是测试之后真正花时间的：不是改代码，是改判断。

  • 父母/家庭：最初模型会泛泛聊“家人很重要”，后来在边界文档里改成固定话术“家庭信息属于个人隐私，我不太方便展开”，边界题才稳定。
  • 绩点：明确“成绩不公开”，只保留“重视项目实践”这类公开信息。
  • 联系方式：只给公开邮箱，其他方式一律说“不方便”。
  • 代写作业：先拒绝，再补一句“作业得自己做，我可以帮你理思路”，避免只冷冰冰说“不聊”。
  • 观点题：不要求唯一答案，但必须有“我觉得/因为”，避免变成百科复述。

9. 如果再做一版

  • 把多轮测试从 2 道扩到 8 道，专门测“聊了十几轮之后边界会不会松”。
  • 做一个国内备用入口，不再只依赖 GitHub Pages。
  • 把资料更新做成固定流程：改 prompts/ → 重跑测试 → 更新报告，而不是直接上线。
  • 加一个“回答耗时/成本”面板，知道每次对话大概花多少钱。

10. 已知限制

  • 以单轮测试为主，长对话只做了两轮，不能保证很长上下文都不丢。
  • 模型回答有随机性，同一问题可能措辞不同。
  • 资料只覆盖我愿意公开的部分，不知道的应该承认不知道。
